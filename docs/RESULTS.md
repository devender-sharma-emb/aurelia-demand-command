# Backtest results

Generated by `python -m aurelia.backtest --seed-start 100 --seeds 20` on 20 held-out synthetic worlds.
The sizing factor (0.8) was calibrated on seeds 0 to 19 with `--sweep`, so it was not tuned on the data
scored here. Raw per-event rows are in `docs/results/backtest_events.csv`, the summary in
`docs/results/backtest_summary.json`.

**Scope.** This tests the decision engine in `decision.py` (campaign sizing, reallocation, approval tiers).
The LLM agents set none of these numbers. Everything is synthetic, and the same generator produced the
data the detector and the factor were built against, so these results show the logic works as designed,
not how it would perform on Aurelia's real data.

## Headline

| Per detected spike (n = 477 of 480) | Campaign alone | With orchestrator |
|---|---|---|
| Spend that chased demand stock could not serve | EUR 7,480 | EUR 5,590 (25% lower) |
| Incremental margin, conservative | EUR 199,917 | EUR 201,124 (+EUR 1,207, CI 654 to 1,719) |
| Incremental margin, with reallocation return assumed | EUR 199,917 | EUR 202,111 (+EUR 2,195, CI 1,560 to 2,809) |
| Demand lost to stockouts | 1,971 units | 1,992 units (no improvement) |
| Markdown units avoided (depends on the 1.8x return assumption) | 0 | 59 |
| Spikes needing a human approval | n/a | 0.8% |

The margin gain is real but small: about 0.6% (conservative) to 1.1% of the margin per spike, because
a EUR 40k budget is small next to the roughly EUR 200k of margin the captured demand earns. The
orchestrator does not create stock, so it does not reduce lost demand. What it does is stop spending on
demand that cannot be served.

## Where it helps and where it costs

| Split | n | Uplift, with reallocation | Uplift, conservative | Wasted spend, alone to orchestrated |
|---|---|---|---|---|
| Stock short of the true lift | 274 | +EUR 4,304 (CI 3,371 to 5,208) | +EUR 2,683 (CI 1,910 to 3,373) | EUR 13,022 to 9,731 |
| Stock sufficient | 203 | EUR -653 (CI -1,313 to -141) | EUR -785 (CI -1,521 to -221) | 0 to 0 |

When stock is enough, the cautious sizing costs a little margin because the projection sometimes
suggests a cut that was not needed.

## Detection and projection

- 477 of 480 injected events detected (99.4%), a median of 2 days after the event began.
- The 14-day lift projection is the weak link: median absolute error 25%, and 41% of projections are too
  high. It uses naive persistence of the last three days of uplift, so it under-reads events still ramping
  up and over-reads events that end early. Every improvement to this projection flows straight into
  the margin numbers.

## Assumptions to state next to any figure from this page

- Units captured are proportional to spend. A different response curve changes the results.
- Reallocated budget returns 1.8x. The conservative column removes this benefit.
- Replenishment ordered now earns no credit inside the 14-day horizon.
- Stock positions are drawn from the same rules the generator uses. Real inventory data would replace this.
- The earlier illustrative figures in the recording deck (for example +91% margin) came from a simplified
  worked example and do not match this backtest.
